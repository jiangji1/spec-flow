# 五维审查清单

对照本次改动逐项检查。发现问题就地修复并说明根因；有业务分歧的列出来等裁决。

## 1 正确性

- [ ] 实现与 spec 口径逐条对齐
- [ ] 边界覆盖：0、空、负数、极大值、并发/重复操作
- [ ] 防重/时序结论核查过 await 边界和按钮禁用窗口
- [ ] 异常路径有处理，不静默吞错

## 2 安全

- [ ] 无注入（SQL/命令/模板）
- [ ] 无 XSS：用户输入不裸拼 HTML
- [ ] 无敏感信息泄漏（密钥、凭证、日志里的个人数据）
- [ ] 权限校验在入口处，不依赖前端隐藏

## 3 性能

- [ ] 无重复请求（同一数据多次拉取）
- [ ] 大列表有分页/虚拟化
- [ ] 渲染无多余重算/重渲染

## 4 可维护性

- [ ] 命名表意，无 magic number
- [ ] 无复制粘贴的重复逻辑
- [ ] 改动面最小：没有需求之外的东西混进来
- [ ] 无多余抽象和防御性兜底

## 5 测试覆盖

- [ ] spec 验收标准每条有测试或验证步骤
- [ ] 删改过的测试说明了理由
- [ ] 测试数据符合业务公式

## 审查结论

- **PASS**：无阻断项和待裁决项；遗留问题均已处理或有明确非阻断结论。
- **PENDING**：存在需要用户裁决或补充信息的待确认项。
- **REJECT**：存在未修复且未获用户明确豁免的阻断项。

报告使用 `<skill-dir>/references/review-template.md`，逐项记录阻断项、待裁决项与豁免项。豁免必须包含用户、理由和对应问题，禁止口头豁免后写 PASS。
