# TDD 测试 /test

按红-绿-重构循环推进；也可用于实现完成后的测试补齐。

## 循环

1. **红**：先写一个会失败的测试，精确对应一条 `AC-N` 验收标准；测试与 Plan 中的 TEST 编号保持可追踪。
2. **绿**：最小改动让它通过，不多写。
3. **重构**：清理重复与坏味道，保持绿。

## 必测清单

- 金额、数量计算（含边界：0、负数、极大值、四舍五入位）
- 状态流转（含非法流转被拒绝）
- 权限与越权
- 防重/防抖：**先核查 await 边界和校验链的网络请求窗口**，再断言「不会重复提交」——校验没 await 住、按钮没禁用期间连点，都不算防重。
- 每条 spec 验收标准至少映射一个测试或验证步骤。

## 红线

- 禁止为了过测试而改弱断言。
- 测试数据符合业务公式，不造自相矛盾的假数据。
- 集成测试用真实边界，不 mock 掉被测链路本身。
