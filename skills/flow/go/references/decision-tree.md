# 分流判定：全流程 vs Vibe 补丁

收到需求先过这张表，判断走哪条通道。**拿不准 → 全流程，宁重勿轻。**

## 走全流程（/analyze → /spec → /plan → /build → /test → /review → /accept → /ship）

命中任意一条即走全流程：

- 核心业务逻辑：金额计算、状态流转、库存、订单
- 权限 / 安全 / 资金相关
- 业务口径变更（报表口径、统计规则、联动规则）
- 动到共享组件、公共配置、公共链路
- 跨模块 / 跨端影响
- 涉及数据结构或接口契约的变化
- 改坏了会污染别人的单据或数据

## 走 Vibe 补丁（/patch）

全部满足才走轻通道：

- 单点修改，影响面一个文件或一小片
- 不动核心逻辑、权限、资金、口径
- 不动共享配置和公共组件
- 失败了容易回滚，不会连锁

典型场景：文案修改、样式微调、明显小 bug、日志/命名调整、小的 UI 展示问题。

## 边界情况

| 情况 | 走法 |
|---|---|
| 看着小，但碰了共享配置 | 全流程（配置改动限定单据类型也属于口径级） |
| bug 修复但根因在核心逻辑 | 全流程（治标补丁先不改，先 /analyze 根因） |
| 线上紧急止血 | 先 /patch 止血并注明临时性，事后回炉全流程 |
| 用户明确说「小改一下就行」 | /patch，但 review 快审不可省 |
