# Vibe 补丁 /patch

小改快速通道：文案/样式可直接改；Bug 先复现定位再改，随后快审与验证。**省的是流程，不省质量。**

## 准入条件（全部满足才走本通道）

- 单点修改，影响面一个文件或一小片
- 不动核心逻辑、权限、资金、业务口径
- 不动共享配置和公共组件
- 失败容易回滚，不会连锁

拿不准 → 回 /analyze 走全流程，宁重勿轻。

## 动作

1. **先分类型**：文案、样式、命名等无行为异常的小改可直接修改；Bug 必须先复现并记录实际现象、触发条件和根因证据。防重/时序问题必须核查 await 边界与网络请求窗口，未定位根因不得直接改。
2. **最小修复**：一句话说明改什么、为什么，然后只修已确认的根因；Bug 同时确定能证明原失败场景的回归验证。
3. **快审**：过 review 清单的三个维度——正确性、可维护性、测试覆盖（安全维度命中注入/XSS 时升全流程）。
4. **验证清单**：先验证原失败场景，再按 /accept 的标准跑完全部可自动验证项；仅无法自动化的事项给出手动步骤（含精确预期值），缺口一并交代。不强制创建全流程工作区文档。
5. **发版**：commit 用中文说清根因；bug 修复注明「治标」还是「治本」，治标的记录后续回炉计划。

## 红线

- 未复现或未定位根因时，禁止把猜测写成确定修复；根因不明或涉及核心口径时升级 /analyze。
- 补丁滚雪球（越改越大）时立刻停，升级为全流程。
- 线上紧急止血的临时补丁，commit 里必须注明临时性与回炉计划。
