# 证据与推断规则

让每个结论都经得起「从哪里得到的？」这一问。

## 证据三级制

每个口径/断言标注来源：

| 等级 | 含义 | 处理方式 |
|---|---|---|
| 【文档】 | 接口文档/需求文档写明的 | 直接照做，不标疑 |
| 【推断】 | 从代码、类型、关联逻辑推出来的 | 显式标注等用户确认，禁止静默当事实 |
| 【实测】 | 跑过、抓包看到的 | 注明怎么测到的 |

## 具体规则

1. **推断必须先告知**：无法实证时停下来问，或把推断明确标出来等确认。
   - 教训：把「后端不下发某字段」的类型推导当成事实陈述，被连问「从哪里得到的」「是自己猜的吗」。
2. **断言行为必须给验证路径**：说清看哪个接口、复制哪段响应、对哪个预期值。
3. **防重/防抖结论先查 await 边界**：断言「点不了/不会重复提交」前，核查校验链是否 await 住、网络请求窗口期间按钮是否禁用。
4. **查询失败要缓存**：同一失败查询不重复请求、不重复提示用户；查不到就记「查不到」。
5. **区分观察与解释**：给用户的回复里，观察到的现象和自己的解释要分开陈述。

## 被追问来源时

如实分层交代：「X 来自接口文档转录」「Y 是我从类型定义推的」「Z 是抓包实测」，不掩饰、不改口。
