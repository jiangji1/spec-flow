# Word 文档处理

产出真正的 `.docx` 文件，不把 Markdown 或纯文本改扩展名冒充 Word。

## 选择工具

1. 优先使用当前项目已有的 Python 或 Node 文档库，不重复引入依赖。
2. 读取内容可用现有 Pandoc、`python-docx` 或 OOXML 解压工具；需要保留结构时，不要只提取纯文本后重建。
3. 创建和常规编辑优先使用成熟库，如 `python-docx` 或 npm `docx`；不要手写整套 OOXML。
4. 没有可用工具时，说明缺少的依赖和用途，经用户确认后再安装。不要全局安装。

## 创建文档

1. 先确认标题、正文结构、表格、图片和输出路径；信息不足时只问影响产出的关键项。
2. 使用标题层级、段落、列表和原生表格，保证内容可编辑。
3. 页面尺寸、页边距、字体和表格宽度要显式设置，不依赖库默认值。
4. 不虚构数据、引用或来源；缺失内容标为待补充。

## 读取或编辑文档

1. 先读取文档结构与内容，再决定修改方式。
2. 编辑前创建副本，原文件只有在用户明确要求时才覆盖。
3. 保留未要求修改的样式、页眉页脚、图片、表格和其他内容。
4. 含修订、批注、文本框、嵌入对象等复杂结构时，先确认工具能否保留；不能可靠处理就停止并说明，不用纯文本重建整份文档。

## 验证与交付

1. 重新打开生成的 `.docx`，确认文件可解析，必需段落、表格和图片数量符合预期。
2. 有渲染工具时检查分页、溢出、乱码和表格布局；不要启动服务或打开浏览器代替 Word 验证。
3. 无法渲染时明确写「未做视觉验收」，给出手动检查步骤，不声称版式已验证。
4. 交付文件链接，并列出内容校验结果与未验证项。
